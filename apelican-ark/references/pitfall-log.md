# 已知事故与回归门禁

## dry-run 曾错误落盘

旧实现只判断“有没有 `--apply`”，因此同时传入 `--dry-run --apply` 时仍会执行恢复；还会把报告和冲突归档写进备份目录。这违背只读预览承诺。

v3 门禁：

- 两个参数由命令行解析器直接设为互斥。
- 未指定 `--apply` 时默认只读。
- dry-run 后目标路径不存在，备份树逐文件 hash 不变。
- 报告和冲突归档只能写到目标用户的 `~/.ark/`。

## 加密依赖缺失曾降级普通 ZIP

旧实现可能在缺少 AES 依赖时警告后继续生成未加密 ZIP，且敏感配置曾先进入普通目录。

v3 门禁：

- 含敏感配置必须有口令与 `pyzipper`。
- 缺任一条件都失败关闭，不生成替代包。
- 敏感配置从源文件直接写入 AES ZIP，不创建明文暂存目录。

## 曾把“配置文件能恢复”写成“账号也能搬走”

文件可复制，不等于账号授权仍有效。登录令牌可能过期，也可能绑定原设备、系统钥匙串或 OAuth 会话。

v3 门禁：

- 账号登录文件、Cookie、系统钥匙串、设备绑定数据和云端 OAuth 会话始终排除。
- 可选 AES 包只处理所选范围内的用户自管敏感配置。
- 回归必须实际完成加密包生成、只读预览、正式恢复和逐文件 hash 比对。
- 对外必须分开写“配置文件已恢复”和“账号需要重新登录”。

## 曾把“会话文件在”写成“聊天记录已恢复”

客户端可能依赖版本、索引或服务端数据。即使本地会话文件和 hash 都在，旧聊天也可能无法在客户端完整显示。

v3 门禁：全量备份只承诺尽力保存本地可见会话文件；恢复后可能只剩记忆可用，不能宣称所有会话可续聊。

## fresh 曾清理目标

v3 将 `--fresh` 改成断言：目标任一所选环境存在文件就停止，不删除、不清空。

## 自动化曾准备 SQL

跨版本直写产品数据库可能破坏目标环境。v3 只导出 JSON 和生成恢复计划，要求使用当前官方接口创建并回读。

## manifest 曾泄露疑似凭据片段

v3 的敏感扫描只保存规则标签与数量，不保存命中行或值。

## 自检参数和校验和曾用错

问题：曾把 `--skill-dir` 传给 `ark_selfcheck.py`，但脚本没有这个参数；修改脚本后未同步 `checksums.json` 也会让自检按设计失败。

修复：

- 从技能根目录直接运行 `python ./scripts/ark_selfcheck.py --json`；脚本会按自身位置找到技能包。
- 代码冻结后再更新 `references/checksums.json`，然后重新运行自检。
- 校验和失败不能被忽略或改成警告后继续打包。

## 发布前最低回归

- Python 编译通过。
- 基础备份预览零写入。
- 备份与恢复的冲突参数返回错误。
- 目录备份 hash 验证通过。
- 旧用户路径自动适配。
- 原文件进入目标用户冲突归档。
- AES 包无口令不可读，缺口令时不创建包。
- AES 包用正确口令可恢复所选敏感配置，恢复后逐文件 hash 一致。
- 账号登录文件与 Cookie 在所有级别、所有加密选项下均被排除。
- 恶意 ZIP 的 `..` 路径被拒绝。
- WorkBuddy 自动化不产生 SQL。
