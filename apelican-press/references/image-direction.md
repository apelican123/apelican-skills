# 封面与正文配图

公众号的图分成两种，不要混：

- **配图**：气氛、隐喻、讲解。可以 AI 生成或用 HTML 卡片渲染。
- **证据**：截图、现场照片、数据图。必须是真实材料。AI 图不准冒充证据。

默认路径：**先调用当前环境里的生图模型**（对话生图、ComfyUI、或其它已接入的图像 API）。没有生图能力时，再用 HTML 做成社交卡片那样的平面图，渲染成 PNG。不要用纯色块或随机几何凑数交差。

参考过的编辑原则（不是某本杂志的复制）：一张封面只服务一个主题、层级少、留白要够、缩略图也能认出来。Kinfolk 一类印刷品证明「呼吸感」能成立；数字封面还要过微信的 2.35:1 列表和 1:1 小图。

## 1. 封面

尺寸：**900×383（2.35:1）**，jpg 或 png，小于 10MB。关键物放在画面正中约 383×383 的安全区，因为列表小图会裁成正方形。

封面要做的事只有三件：让人感到这篇文章的语气、看出主题物件、在小图里仍然可识别。微信标题已经显示在封面上，**不要把完整标题再画进图里**。最多一个短词（两字主题，如「纸墨」），可有可无。

生成前先从正文抽出：

1. 一个中心判断
2. 一种情绪（慢 / 冷 / 急）
3. 一个可视物件（台灯、纸页、路口、线路图），不要五个物件挤在一起

### 封面构图

- 一个主体，背景干净
- 主体周围留出至少 30% 空
- 颜色不超过主题模板的三色：纸色、墨色、一种强调色
- 光要平、要散，不要体积光、不要黄金时刻逆光大片

三套模板的默认调性：

| 模板 | 封面该长什么样 |
| --- | --- |
| 人文纸墨 | 静物或空房间一角，暖纸色，暗红点缀，像副刊 |
| 科技青简 | 一个结构清楚的物件或极简示意图，冷灰底，一条蓝 |
| 社会热点 | 一个空场景或一件物证感的东西，白底或浅灰，朱红极少 |

### 封面提示词骨架

把方括号换成当篇事实。一次只生成 1–2 张，选更干净的那张。

```text
Editorial still-life, one [object] in the center third of a 2.35:1 frame,
large empty paper-colored negative space, flat even light, limited palette
[paper] [ink] [accent], quiet magazine photography or flat editorial illustration,
no text, no logo, no watermark, no collage.
```

禁止词（写进 negative / 不要出现）：

```text
oil painting, impasto, cinematic lighting, volumetric fog, dramatic chiaroscuro,
hyperreal skin, plastic skin, beauty portrait, 3D render, Unreal Engine,
crowded collage, fake UI, fake screenshot, extra fingers, watermark,
anime eyes, chibi, 二次元, ornate baroque, stock photo handshake
```

## 2. 正文插图

### 插在哪

不是每一段都配图。只在这些位置考虑一张：

- 每个真正换场景的二级标题附近，最多一张
- 全文最重要的那个判断，可以多一张
- 步骤、对比、结构需要被「看见」时

数量上限：封面 1 张 + 正文 **2～4** 张。短文（不到 800 字）正文最多 2 张。没有视觉任务的纯观点段，用引用和留白，不硬配图。

每张图下面必须有一句图注，说明读者该看到什么，并标明这是配图不是现场：

```markdown
![台灯停在旧桌面上](./images/01-lamp.jpg)

图注：配图。对应「把夜晚还给街道」这一节的物件，不是某条真实街道的照片。
```

### 按文风选图种

| 文风 | 该生成什么 | 不要生成什么 |
| --- | --- | --- |
| 人文 / 随笔 | 静物、空椅子、窗、纸、手的局部（无脸） | 假风光大片、假人物故事照 |
| 科技 / 教程 | 扁平讲解图、流程、爆炸示意、界面线框 | 发光笔记本电脑海报、赛博城市 |
| 论文 / 综述 | 关系图、时间轴、对比柱、结构示意 | 假实验室、假论文截图 |
| 社会热点 | 空荡物件、文件叠、街道设施，不出现可辨认的人脸 | 假新闻现场、假冲突、假群众 |

讲解图优先「能看懂结构」，不是「好看」。箭头、分栏、编号可以有，但不要做成 PPT 智能图形。

## 3. 风格底线

整体：干净、留白、一点文艺，不要复杂。

匹配文风：人文慢、科技清、热点利落。颜色跟当前 CSS 模板走，三套不要混。

视觉避雷（看起来像廉价 AI 的特征，出现任意两条就重做）：

- 油画笔触、厚涂、假伦勃朗光
- 皮肤蜡像、眼神空洞、手指数量不对
- 画面塞满装饰和雾
- 图上写了标题、水印、乱码英文
- 五个隐喻物件拼在一张里

要更「真」：平光、真实材质（纸、木、金属）、轻微颗粒可以，戏剧光不行。静物和空景比人脸稳。

动漫：只有用户明确要求才用。必须是**平面图形 / 粗线平涂**，像海报或绘本，不是大眼二次元、不是日漫赛璐珞、不是 3D 手办。

## 4. 生图失败或没有生图模型时

退到 HTML 卡片，模仿「一张社交卡片」而不是海报墙：

1. 复制 `templates/cover-fallback.html` 或 `templates/inline-fallback.html`
2. 只改：短词、一句说明、背景色、强调色
3. 用 Playwright / `html-card-render` 把 `.poster` 截成 PNG
4. 禁止 Google Fonts 外链；用系统字体栈

HTML 卡也要遵守：一个词或一个几何物、大留白、不要胶囊按钮、不要三栏 KPI。看起来像 PPT 就重做。

仍没有渲染能力时，停在「缺图」，不要用纯色矩形冒充封面。wenyan 没有 cover 文件会失败。

## 5. Agent 执行顺序

1. 定模板（人文 / 科技 / 热点）
2. 列配图清单：封面 1 + 正文 N，写清每张对应哪一节、什么物件、是不是证据
3. **先调生图模型**；每张看一眼，不合格就改提示词再生成一次，不要连做五版
4. 生图不可用 → HTML 卡
5. 把图放进文章目录，Markdown 用相对路径，补图注
6. 再 `wenyan render` / `publish`

用户自己提供了真实照片或截图时，真实材料优先，AI 图让路。真实截图不得重绘成假界面。

## 6. 验收

- [ ] 封面 900×383，中心物体在 1:1 裁切后仍在
- [ ] 图上没有完整标题、没有水印
- [ ] 正文图有图注，且没把配图写成现场
- [ ] 数量没有超过 封面1 + 正文4
- [ ] 颜色能看出是当前那套模板
- [ ] 没有油画光、蜡像脸、二次元大眼（除非用户要平面动漫且已做成平涂）
