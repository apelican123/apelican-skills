# 验收清单（铸造模式）

## 五层结论 + 部署验证

| 层级 | 需要的证据 | 铸造模式何时完成 |
|---|---|---|
| 构建 | 单元测试、类型检查、固定依赖、dry-run | Worker 零依赖，语法经部署 API 校验（上传即构建） |
| 部署 | Cloudflare 上传成功、Secret 写入成功、workers.dev 可用 | 第 5 步部署完成即验证 |
| 生产传输 | initialize、notifications/initialized、ping、tools/list、错误认证 | 部署后验证脚本跑通（见 [verification.md](verification.md)） |
| 真实调用 | 获准的无副作用调用，检查 JSON-RPC 与 `isError` | 用户同意时执行一次只读调用 |
| ChatGPT 连接 | ChatGPT 成功发现预期工具与元数据 | 用户粘贴 URL 后确认 |
| 用户验收 | 用户用自然语言完成目标请求 | 用户反馈 |

一层通过不能替代另一层。铸造模式自动化完成前四层；「ChatGPT 连接」和「用户自然语言验收」必须由用户确认，禁止代写结果。

## 测试权归属

- 真实工具调用可能消耗额度或读取私人数据，应由用户指定谁来测；
- 用户说「我来测试」后，停止代测；保持交付物与验证方法，不把停止测试理解为禁用；
- 用户只说「可以连接」，记录 ChatGPT 连接通过，不推断真实工具调用也成功。

## 交付说明（最终给用户的内容）

- 完整链接（注：链接即凭据，提示妥善保管）；
- ChatGPT 配置三步：Add MCP server → 粘贴链接 → 认证选 No authentication；
- 预期工具数量和名称；
- 一条安全的只读验收提示（例：「用 search_documents 搜一下 XX」）；
- 成功、认证失败和上游失败的预期差异；
- 链接作废/轮换方法（重生成 LINK_TOKEN Secret）；
- 哪些检查尚未执行（如真实调用未测、ChatGPT 连接未确认）。

## 铸造模式 vs 设计模式

- 铸造模式（默认）：自动执行到「部署 + 传输验证」完成，交付链接并列出仍由用户负责的层级；
- 设计模式（用户只要方案时）：全部标「待实施」或「待验证」，输出五层清单但不执行任何部署。
