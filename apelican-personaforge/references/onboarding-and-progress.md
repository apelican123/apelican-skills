# 新手引导与进度反馈

本文件规定 2.0 的对话体验。目标不是让用户学完一套术语，而是让他始终知道“现在做到哪里、我需要做什么、怎样判断成功”。

## 开场只问真正缺的信息

先用一句话确认目标，例如：

> 我会把你现有的这个能力做成 ChatGPT 可以直接调用的个人插件。你不用先了解 MCP 或隧道，我会每一步告诉你该做什么、看到什么才算成功。

优先读取用户已经提供的文件、项目和链接。只有无法从现有材料判断时，按顺序一次问一个：

1. 你想在 ChatGPT 里完成什么具体事情？
2. 你现在有 API 文档、MCP 地址，还是只有一个 Skill/想法？
3. 这是自己用、给少量可信的人用，还是准备公开发布？
4. 你是否已经有 Cloudflare 账号和可部署的 Worker 项目？
5. 能力涉及只读数据，还是会写入、删除、付款、发帖或发信？

不要让零基础用户自己选择 REST 翻译、MCP 代理、OAuth 或 Tunnel。先由技能判断，再用一句普通话解释为什么。

## 每一步固定回应

每完成一个可检查动作，给出四行以内的反馈：

```text
已完成：刚刚实际做了什么。
你会看到：用户在页面或终端应看到的结果；若由 Agent 自己验证，直接给验证结果。
下一步：只给紧接着的一个动作。
如果不同：最可能的一个分支和怎样把报错/截图交回来。
```

没有实际执行或读回时，不写“已完成”。可以写“已准备”或“等待你在页面点击”。

## 进度地图

开始时给一个短进度，不展开所有工程细节：

```text
[1/7] 确认你已有的能力
[2/7] 测试原服务能否调用
[3/7] 生成 Cloudflare 插件项目
[4/7] 创建你的专属链接
[5/7] 部署并做安全检查
[6/7] 接入 ChatGPT
[7/7] 实际调用与交付
```

完成一步后更新状态。发生分支时只插入一个临时步骤，例如“[4a/7] 修复 Cloudflare 登录”，不要重新编号整套流程。

## 能自动做的事情直接做

在权限允许且不会产生高风险外部影响时，技能可以直接：

- 读取项目结构、API 文档和现有配置；
- 生成代码、测试、配置模板和本地用户链接材料；
- 运行类型检查、dry-run、协议审计与无副作用调用；
- 查看 Cloudflare 当前项目和旧 version ID；
- 生成随机 Token 和摘要，但不把真实 Token 写进日志、文档或公开文件。

部署生产、创建/替换 Secret、执行写操作、公开提交审核等动作，仍按用户授权和平台确认要求执行。

## 用户需要手动操作的页面

当必须由用户点击时：

1. 先说打开哪个产品的哪个页面；
2. 一次只给当前页面的点击路径；
3. 告诉用户应该看到的字段或按钮；
4. 请求截图时提醒遮住完整专属 URL、Token、API Key、邮箱和账号信息；
5. 用户回来后先核对结果，再继续下一步。

页面名称可能变化。若当前官方文档或实际截图与旧说明不同，按当前页面走，并把差异记录到排障文档；不能为了继续流程假装按钮存在。

## 默认专属链接说明话术

第一次生成链接时，用普通话同时说清方便和风险：

> 在 ChatGPT 里你只需要选择“无身份验证”，再粘贴这条完整链接。验证其实在 Cloudflare 完成：链接里的随机部分就是访问密钥。谁拿到完整链接，谁就可能使用这项能力，所以不要截图、公开或转发；如果泄露，我会帮你只撤销这一条并生成新链接。

多人场景再补一句：

> 每个人都会得到不同的用户名标识和随机密钥。用户名只是标签，不是密码；A 的密钥放到 B 的链接里也必须连接失败。

## 常见分支怎么带

### 只有 Skill，没有 API/MCP

先说明 Skill 文件本身不能被 ChatGPT 当作远程工具调用。帮助拆出最小可调用接口，不制造“上传 Skill 就自动变插件”的假象。

### 没有 Cloudflare 账号

先完成注册和登录，不一次讲 Worker、Secret、域名和 OAuth。登录成功后再回到第 3 步。

### 已有一个 MCP 链接

先做 `initialize`、`tools/list` 和只读调用。不要默认重写；能安全代理就保留上游能力。

### 有多人使用

- 各自部署：默认推荐，天然减少相互连接和密钥共用。
- 一个 Worker 管少量可信用户：一人一 URL、一人一摘要 Secret，做跨用户错配测试。
- 大量用户、独立账户数据或公开发布：切换 OAuth 2.1，不继续堆链接 Token。

### 用户看到“连接失败”

先判断是哪一层：链接被 Cloudflare 拒绝、MCP 初始化失败、工具 schema 无效，还是 ChatGPT 页面权限/策略不允许。一次只验证一层，具体见 [troubleshooting.md](troubleshooting.md)。

## 结束时不要只说“部署成功”

必须让用户看到一次真实结果：在 ChatGPT 中启用插件，发出一条自然请求，确认选中了预期工具并返回真实只读数据。然后交付撤销链接、轮换密钥和回滚 Worker 的具体路径。
